# What this preparation carries forward

The first effort produced replayable analyses and an editable poster, but setup and collection consumed too much research time.
Undiscovered account-level skills, later-arriving candidate PRs and changing packaging expectations made the initial task harder; these were shared setup decisions, not evidence about the effectiveness of the tested skills.

| Recurring problem | Prepared response |
|---|---|
| Conventional subjects hide DataLad run records from its native parser | Preserve the record; use the tested, explicit compatibility adapter and report that qualification. |
| Git history exists but annex payloads do not | Test a real upload and independent anonymous retrieval with hashes. |
| Cluster login works but execution or transfers fail | Transfer the exact environment and run a small scheduled analysis; return complete records through the local host. |
| Worktrees inherit mutable host configuration | Pin tracked files and submodules; prepare each checkout and inspect its actual loaded instructions. |
| New checkouts lack hook approval or capture | Reuse only identical approved hooks, then verify real file events and hosted checkpoints. |
| Missing packages or conflicting lockfile merges | Add packages to root `pixi.toml`; retain validated locks on separate one-commit snapshot branches. |
| Logs or whole checkouts are scattered outside the research object | Merge ordinary experiment files and complete logs; retain replay refs and annex payloads. |
| Too much prose, too few useful figures | Short skill entrypoints with conditional references; require figures and visual inspection. |

For the next host, run three small probes concurrently before research: local analysis/replay plus annex retrieval; a scheduled cluster job and return transfer; native capture in a fresh prepared checkout.
Use their retained failures to fix the host once.
This host has completed the local and cluster routes; the capture module records its separate cases.
A successfully configured tool is not a passed probe.

The intervention starts from [PR23](https://github.com/con/skills/pull/23), with our adaptations on `codex/pr23-stamped-rerun`.
[PR24](https://github.com/con/skills/pull/24) and [PR26](https://github.com/con/skills/pull/26) remain named candidates; including them later requires declaring a changed intervention.
The five adapted entrypoint bodies total 2,652 tokens versus 4,779 before adaptation using `o200k_base` (references and frontmatter excluded); this is a size comparison, not a quality or efficacy result.

The [retained candidate review](https://github.com/leej3/stamped-ai-research/blob/main/research/skill-candidates/REVIEW.md) identifies concrete upstream improvements at its pinned revisions:

- PR23: preserve inspection-versus-execution evidence, allow already-authorized scoped repairs, then reassess; we adapted these instructions directly.
- PR24: keep external scientific grading, bounded task stages and budgets; turn the proposed installation and replay steps into executable trials.
- PR26: keep checklist provenance and regression fixtures; require absent generated outputs, a rejected no-op, exact table labels and explicit missing-value rules.
  Compose existing hooks rather than replacing them.
  Report tested scope precisely.

This preparation adds the missing practical evidence: a community-library analysis, negative controls, two replay generations, actual remote payload retrieval, and native capture across checkout types.
The modest scientific fixture is an integration check, not a new skill-efficacy result.

Existing withheld pilot captures retain their prior hold, and the general sensitivity threshold remains undecided.
